# 系统设计总结（2026-10-25）

平台：Tang Primer 25K（GW5A-LV25MG121）。周期：7 天，已用约 1.5 天。

## 1. 总目标

交付「PC 上位机（参数控制 + 光标显示） + FPGA 实时合成器」。硬指标：≥4 复音（做 32 声部）、≤10 ms 延迟（目标 ≤5 ms）、音频必须由 FPGA 逐样本生成。

## 2. 总体结构

```text
                ┌──────────── FPGA ────────────┐
MGC3130 ──I2C──▶ 锁存 → 光标 → 出音规则 → 事件表
                                    │
                                    ▼
                            32 声部 × 2 振荡器（波表 + 包络 + 滑音）
                                    │
                                    ▼
                            混音 → FX → I2S → DAC

PC ──UART──▶ 参数下行（波表、包络、门控、音阶、FX）
PC ◀──UART── 遥测上行（光标、当前音符、声部占用）
```

PC 负责设计音色与显示轨迹，FPGA 负责实时发声。

## 3. 输入链路（已完成并验证）

| 环节 | 做法 | 关键参数 |
| --- | --- | --- |
| 传感 | MGC3130 电容三维 | 200 Hz，X/Y/Z 16 bit |
| 校准 | 每次录音调 `gestic_force_calibration()` | 接收器 `--force-calibration` |
| 光标 | 绝对映射，Z 控制跟随速率 | alpha 1.0→0.12，接合 30000 / 释放 36000 |
| 抗抖动 | 每帧位移 ≤0.02、触控冻结、接触前回滚、抬手平滑接续 | — |
| 触控漂移 | 接触使质心偏移 (−10071, +1433)，冻结规避 | 实测 `lead_20261025-121454` |

## 4. 事件链路（已完成并验证）

```text
光标轮廓 → 变分分段（Potts，DP 精确解）→ 音符表
代价 = Σ(轮廓 − 音级)² + λ·段数，段长 ≥ 4 tick
```

| 机制 | 说明 |
| --- | --- |
| 密度 | 滑块 → λ = 0.5·60^density |
| 门控 | `touch`（接触发声，时值=接触时长）/ `bow`（左右往返） |
| 同音重复 | 门控切分，落在同一音级 |
| 大跳 | 跨度 ≥3 音级且快速通过时不出经过音 |
| 时间模型 | 循环录制：绝对时间 → tick，超 128 回绕，后圈覆盖前圈 |
| 长度 | Auto length：按小节向上取整跟随录制长度 |

## 5. 音色链路（方案已定）

```text
① 采集一次划动（1.5–3 s）
② 时间去归一化 → 相位 0..1      ← 全部关键：手慢不再损失高频
③ 重采样 1024 点
④ 限带 32 次谐波                ← 把"画乱"从故障变成风格
⑤ 1024×16 bit 波表 → UART 下发 BRAM
⑥ FPGA：相位累加 → 查表 → 包络
```

已验证：线性映射平淡、tanh 波整形变亮、相位失真出金属感；固定旋律下四种音色可明确分辨。

## 6. 合成器（待写 RTL）

```text
32 声部 × 2 振荡器 = 64 个振荡器（≥32 达标）
每振荡器：1 相位加 + 3 查表 + 3 加权 + 1 包络 ≈ 13 clk

50 MHz（现有基线）：1041 clk/样本，64 × 13 = 832 clk → 占用约 80%
100 MHz（需加 PLL）：2083 clk/样本，占用约 40%

结论：50 MHz 下没有余量做 FX，必须二选一
      A. 加 PLL 提到 100 MHz 并完成时序验证
      B. 保持 50 MHz，声部减到 16，或把 FX 放到更低优先
```

> 以上为**估算**。综合与 P&R 报告出来之前，不得称为已验证架构。

| 资源 | 用量 | 25K 占比 |
| --- | --- | --- |
| 波表 3×1024×16 | 48 Kb | 4.8% |
| 相位/包络 RAM | 7 Kb | 0.7% |
| FX 延迟线 + 混响 | 128 Kb | 12.7% |
| DSP 乘法 | 12.3 M/s | 0.4% |

时分复用已被组委会明确认可，无需物理并行。

## 10. 走过的弯路

| 尝试 | 结论 |
| --- | --- |
| 波导弦 | 音色调不出，弃用 |
| 分段 FFT 反推音色 | 两次统计压缩，区分度不足，弃用 |
| FM 调制波 | 可用但关联弱，备选 |
| **相位映射波表** | **采用** |

## 11. 一句话

手势曲线决定演奏（音高、节奏、力度），一次划动决定的波表决定音色，FPGA 只负责把两者实时合成。

## 12. 评审修订（2026-10-25）

### 12.1 两个阶段必须分开

```text
当前阶段（本设计）：
  MGC3130 → PC Capture & Loop → EventTable → FPGA 声部引擎 → I2S

后续扩展（不属于当前阶段）：
  MGC3130 → FPGA 实时输入解释 → FPGA 声部引擎 → I2S
```

FPGA **不重新实现** PC 的曲线滤波、Potts 分段、门控与音符生成。原第 9 节 D3 的「接输入，复现 PC 光标与出音规则」降级为 Live 扩展，不与主流程并列，否则会出现两套旋律来源。

### 12.2 音色采集与旋律采集必须分开

```text
Lead 旋律采集：曲线 → EventTable（note / duration / velocity）
Lead 音色采集：一次划动 → 单周期波表 → SynthConfig
```

同一条曲线不同时决定音符和波表，否则操作者无法判断差异来自旋律还是音色。

波表补充规格：

| 项 | 规定 |
| --- | --- |
| 表数量 | A / B / C 三张，A=主音色，B=加厚，C=低八度 |
| 振荡器选表 | 振荡器 1 读 A，振荡器 2 读 B；C 由声部模式决定 |
| 共享 | 所有声部共享同一组表 |
| 传输 | 分块 + CRC16 + 版本号 |
| 切换 | shadow → APPLY → active，切换在 Loop 边界生效 |
| 抗混叠 | 表限带 32 次谐波；若音高 + bend 使 32·f 超过 Nyquist，按音高动态降低谐波数 |
| BRAM 读延迟 | 按 2 clk 计入手册流水（已在 13 clk 估算内含 2 clk） |

### 12.3 协议必须冻结为一份

| 区间 | 用途 |
| --- | --- |
| `0x00–0x44` | Loop 控制面（已存在，不改） |
| `0x48–0x5c` | Synth patch：timbre、ADSR、FX mix、glide、vibrato、bend |
| `0x60–0x7c` | Wavetable upload：分块地址、数据、CRC、APPLY |
| `0x80–0x9c` | Telemetry 与诊断：声部占用、延迟计数、测试模式 |

规则：

```text
① 配置先写 shadow，显式 APPLY 后才生效
② 波表分块带 CRC，校验通过才切换 active
③ 配置只在 Loop 边界或 APPLY 时生效
④ UART 阻塞不得影响 48 kHz 音频（事件与音色各用独立队列）
⑤ 测试模式用独立 CSR，不与演奏路径混用
```
