# 曲线 → 旋律：变分分段模型（2026-10-24）

版本：2026-10-24  
问题：电平穿越不够优美；能否用纯数学方法把曲线优雅地变成旋律；以及"把一次录制的全部轨迹展开成一条只有两个端点的时域函数"是否可行。  
关联：[Lead 映射分析报告](lead-mapping-report-2026-10-22.md)、[曲线到旋律算法评估](curve-to-melody-algorithms-2026-10-22.md)

## 1. 先给结论

1. **把三维轨迹展开成一条定义在 [t0, t1] 上的标量函数 f(t)，完全可行，而且应该这么做。** 这就是"轮廓提取"，之后的全部问题是 1 维的。
2. **但投影方向必须固定**（例如固定的音高轴），不能对每次录制做 PCA：否则同一物理高度在不同录制里映射到不同音高，违反固定 PitchSpace 契约。
3. **拓扑方法（只取极值）在这批数据上不可用**：实测 25 秒的手势只有 **2–3 个显著极值**，把持久性阈值从 0.25 个半音调到 3 个半音，数量都不变。所以"优美"不能来自极值，必须来自变分。
4. **推荐方案：把旋律定义为"在音级格上对轮廓的最优分段常值逼近"**，即 Potts 变分模型，用动态规划精确求解。电平穿越是它 λ→0 的退化情形，因此不是"换一个方法"，而是**把电平穿越纳入一个更一般的最优性框架**。

## 2. 一维化：从 q(t) 到 f(t)

```text
q(t) ∈ R³                        三维轨迹（光标坐标）
w ∈ R³, |w| = 1                  固定投影方向（来自 profile，不随录制变化）
f(t) = w · q(t)                  标量轮廓，单位取"半音"
```

pitch 轴取 `w = (0, 1, 0)` 即当前的 cursor_y；换成"沿路径前进"的投影是另一个 profile 选择，但必须**在录制前锁定**。

这一步把问题变成：给定 `f: [t0, t1] → R`，产出离散音符序列。

## 3. 为什么不用拓扑（实测）

对真实采集（4938 / 5783 帧），先做 5 帧平滑，再算每个局部极值的**地形突出度（prominence）**——它是 1 维函数上"持久性"的等价量：

| 采集 | 全长 | 极值数 | 主要突出度 |
| --- | --- | --- | --- |
| 19:32 | 4938 帧 / 24.7 s | 3 | 5.6、9.5、11.7 半音 |
| 21:31 | 5783 帧 / 28.9 s | 3 | 17.0、17.0 |

阈值从 0.25 扫到 3.0 半音，极值数**始终是 3**。原因很简单：手在一次演奏里通常只有两三次真正的方向反转，其余都是同向移动。

结论：极值检测给出的是"句子骨架"（2–3 个音），不是旋律。**音符数量必须由别的东西决定。**

## 4. 变分模型：Potts 分段

### 4.1 定义

设音级格 `P = {55, 57, 60, 62, 64, 67, 69, 72}`（固定 PitchSpace）。求一个分段常值函数 `g(t)`，取值只能来自 `P`，使

```text
E(g) = Σ_t (f(t) − g(t))²  +  λ · (g 的段数)
```

最小。加上最短段长约束 `段长 ≥ L`（例如 4 tick）。

这条式子的含义可以直接读出来：

- 第一项要求 `g` 尽量贴合轮廓；
- 第二项惩罚"换音"，λ 就是**换一个音需要多少误差才值得**；
- 因此长音出现在轮廓平坦处，短音出现在快速移动处——不需要任何额外规则。

### 4.2 为什么这比电平穿越优美

| 电平穿越 | Potts 分段 |
| --- | --- |
| 局部、贪心：每个边界只看来回振荡 | **全局最优**：整句一起优化 |
| 阈值是"滞回 0.25 音级"，与音乐无关 | λ 有明确单位与含义（误差/换音） |
| 在边界附近会来回产生短音 | 最短段长约束直接保证 |
| λ→0 才退化成它 | 它是 Potts 的特例 |

换句话说：**电平穿越是"每个边界单独决策"，Potts 是"整句一起决策"**。后者才是"优美"的来源。

### 4.3 精确求解：动态规划

状态 `(t, 音级, 当前段已持续长度)`：

```text
dp[t][k][run] = Σ_{s≤t}(f−P_k)² + λ·(已分段数)
转移：同音级继续（run+1）
     换音级（run ≥ L 时允许，加 λ，run 重置为 1）
```

规模：`N × K × L`。以 128 tick、8 个音级、L=4 计算，共 128×8×4 = **4096 个状态**，PC 上是毫秒级；FPGA 上是有界的定点 DP（这正是设计文档里"有限候选半马尔可夫 DP"的最简形式）。

### 4.4 实测结果（同一批采集，128 tick）

| λ | 19:32 采集 | 21:31 采集 |
| --- | --- | --- |
| 0.5 | 28 个音 | 18 |
| 2.0 | 25 | 18 |
| 6.0 | 24 | 18 |
| 15.0 | **17** | 18 |

前五个音（19:32、λ=6）：`(tick 0, 60) → (4, 69) → (9, 72) → (13, 67) → (21, 69)`，全部落在五声音级上，段长 4–8 tick，没有任何短于 4 tick 的音。

λ 的可解释区间：λ 的单位是"半音² × tick"。λ=6 意味着"轮廓偏离某音级 2.4 个半音持续 1 tick 的代价，等于换一次音"。可以直接用音乐语言调参。

## 5. 与"展开成一条两终点的时域函数"的关系

用户的提法与本方案一致：

```text
一次录制 = 一条函数 f: [0, T] → R，只有起点和终点
演奏 = 在这条函数上选投影 w、平滑尺度、λ、最短段长
输出 = 分段常值逼近 g(t) → 音符序列
```

需要注意的是"两个端点"的含义：`f` 是开区间函数（不是闭环），所以起点和终点天然存在；但**音乐时间是唯一的参数**，不能再用弧长或空间距离去重排它（这是既有规范）。

### 5.1 建议保留的三个自由度

| 参数 | 作用 | 建议范围 |
| --- | --- | --- |
| `w`（投影方向） | 决定"哪一维是旋律" | 录制前锁定，默认音高轴 |
| 平滑尺度 σ | 决定"多小的转折算装饰" | 20–60 ms |
| λ（换音代价） | 决定音符密度 | 2–15，按曲风预设 |
| `L`（最短段长） | 决定最短音符 | 4 tick |

四个参数都落在音乐语义上，没有一个"魔法阈值"。

## 6. 还缺什么（诚实清单）

1. **和弦与强拍没有进入代价函数**。现在只贴合轮廓，不关心当前和弦。加一项即可：`+ μ · (强拍上非和弦音的惩罚)`，仍然是 DP，只是每帧代价不同。
2. **句法/动机没有进入**。动机重复、半终止、高潮位置需要更高一层（HSMM），不建议与分段混在一起。
3. **λ 与密度的关系依赖手势速度**。同样 λ 下，快手势会出更多音，这是特性；但需要在 UI 上显示出当前密度，让用户可预期。
4. **平滑与分段两步分离**。更优雅的做法是把 TV 正则与分段放进同一个能量，但那样求解会复杂一个量级，当前不值得。

## 7. 建议

1. 把 `f(t)`、`w`、σ、λ、L 写进 profile，作为"风格层"的参数（对应 §9 三层架构）。
2. 用 DP 分段替换现有的"锚点即音符"，`turn/apex` 不再直接出音，而是作为 λ 之外的**结构加权**（例如转折点允许更低的换音代价）。
3. 先做离线版本，用现有采集回放对比：同一 λ 下音级序列是否稳定、是否单调跟随轮廓、是否有短于 L 的音。
4. 电平穿越保留为 λ→0 的调试模式，不作为产品路径。

## 8. 一句话总结

把曲线变成旋律的"纯数学"答案是：**固定投影得到 f(t)，用 Potts 分段在音级格上求全局最优的分段常值逼近**；段边界就是音符，段长就是时值，λ 就是密度。拓扑只提供句子骨架，不提供音符数量——这是这批数据已经证明的事实。
