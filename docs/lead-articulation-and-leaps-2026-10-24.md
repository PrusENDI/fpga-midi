# Lead 的发音与跳进：把"何时"和"多高"分开（2026-10-24）

版本：2026-10-24  
问题：操作者如何让**同一个音做几个短节拍**，以及如何做**跨越数个音级的大跳**；如何在保持掌控感的同时保住自由度。  
关联：[变分分段模型](curve-to-melody-variational-2026-10-24.md)、[映射分析报告](lead-mapping-report-2026-10-22.md)

## 1. 现状诊断（实测）

| 操作 | 结果 | 原因 |
| --- | --- | --- |
| 快速大跳 | 插入经过音：`57(60) 60(4) 64(9) 67(55)` | 低通把阶跃抹成斜坡，中间音级各占 ≥4 tick，够资格成段 |
| 同音重复 | 1 个音，持续整段 | 分段常值逼近要求相邻段音高不同，结构上无法重复 |

结论：

1. **大跳是"能做但不可控"**：能否干净跳过去，取决于阶跃在 tick 尺度上有多陡。长采集（20 s，1 tick≈157 ms）下 100 ms 的甩动一定跳过去；短采集会被 4 tick 约束拆成经过音。
2. **同音重复是"结构上不存在"**：一维映射只有一个自由度，无法同时表达"多高"和"何时再弹"。

## 2. 缺的那一维：X 轴是空的

当前绝对光标里，`cursor_x` 只用于绘制，**完全不参与音乐**。`b_abs = cursor_y` 只用了 Y。所以还有整整一个轴可用于表达，而且不需要改坐标映射。

这就是给"何时"松绑的地方。

## 3. 建议的演奏语言（弓弦模型）

把光标当成弓：**上下决定音高，左右决定运弓，高度决定力度**。

| 轴 | 音乐含义 | 操作 |
| --- | --- | --- |
| **Y（上下）** | 音高 | 抬高 = 音高升高；快速移动 = 大跳 |
| **X（左右）** | 发音 / 运弓 | 左右拉锯一次 = 同一个音再触发一次；拉伸越快 = accent 越强 |
| **Z（高度）** | 力度 / 音色 | 贴近 = 响、亮；抬远 = 轻、暗；快速下压 = 重音、retrigger |

由此得到三种用户直接可做的动作：

| 想要的效果 | 动作 |
| --- | --- |
| 同一个音弹 3 个短音 | 保持 Y 不动，X 左右来回 3 次 |
| 跨 5 个音级的大跳 | Y 快速移动（不拖泥带水） |
| 长音 | Y 和 X 都停住 |
| 重音 | Z 快速下压一次 |

## 4. 实现方案

### 4.1 同音重复：X 的极值就是重触发点

在分段结果之上加一层"发音分割"：

```text
对每个分段 [start, end) 且音级为 ℓ：
  取该区间内 cursor_x 的局部极值 tick 集合 E
  对每个 e ∈ E：在 e 处把段切成 [start, e) 与 [e, end)，两者音级都是 ℓ
  第一个音的 gate 由 X 的速度决定：慢 = legato，快 = 短促
```

要点：

- **音高不变**，只改变"再触发一次"；这正是分段模型做不到、而演奏需要的事。
- 极值检测天然带滞回：X 需要往返超过一个死区（例如 0.03 归一化）才算一次运弓。
- 每一次运弓的速度 → accent；X 的停留时间 → gate。

### 4.2 大跳：加一条"跳进优先"规则

现有约束已经提供了基础（中间段必须 ≥4 tick 才可能存在）。需要补的是让意图更明确：

```text
若 |Δℓ| ≥ 3 个音级 且 完成时间 < 2 tick：
    禁止中间经过音，直接成段
```

这条规则只影响"是否允许中间段"，不改变音高映射，也不会让短采集里的慢速移动跳级。

### 4.3 记录与诊断

每个事件新增：

```text
segment_index
reattack            true / false        是否由 X 运弓切开
bow_speed           该次运弓的速度（→ accent）
gate_ratio          由 X 速度决定
```

UI 上把 X 的往返画成短竖线（运弓标记），操作者能直接看到"这一笔被识别成几次发音"。

## 5. 为什么这能同时保住掌控感和自由度

- **掌控感**来自"每次发音都能看见"：Y 决定音高、X 决定几次发音、Z 决定力度，三者互不干扰。
- **自由度**来自"一次连续性动作可以表达多件事"：同一段轨迹里，手可以边抬边拉锯，同时得到音高变化与多次触发。
- 三种通道的分工是**正交的**，不会出现"抬高既改音高又改节奏"这种耦合。

## 6. 与"展开成一条函数"的关系（回答：是否相悖）

**不相悖，但必须把模型从标量推广到向量，并把边界写清楚。**

### 6.1 严格表述

```text
γ: [t0, t1] → R³                 一次录制 = 一条有向曲线，只有两个端点
π: R³ → R    π(q) = q · e_pitch  音高功能（一个标量场）
α: R³ → R    α(q) = q · e_bow    发音功能（另一个标量场）
p(t) = π(γ(t)),  a(t) = α(γ(t))  两条标量信号，同源于同一条 γ
```

- `p(t)` 的 Potts 分段给出**音高与音长**；
- `a(t)` 的局部极值给出**再触发点**；
- 两者都是同一条曲线 γ 的**泛函**，没有任何外部信号。

所以"展开成一条只有两个端点的时域曲线"依然成立——`γ` 就是那条曲线，`t ∈ [t0, t1]`。变化的只是：**音乐不再是"一个标量的函数"，而是"同一条曲线的几个泛函"**。

### 6.2 为什么不能只用一个标量

一个标量函数 `p(t)` 在任一瞬间只有一个值。要同时表达"多高"和"何时再弹"，需要两个独立自由度——这是**信息量**问题，不是算法问题：

- 只用 `p(t)`：相邻段必须换音级，否则无法区分"一个新音"与"同一个音延续"；
- 想要同音重复，必须引入第二个可分量的信号（X 的折叠，或 Z 的脉冲）。

**代价必须说清**：如果坚持只有一个标量函数，就必须放弃"同音重复"或放弃"独立控制发音"。两者不可兼得。

### 6.3 三种方案，只有两种自洽

| 方案 | 结构 | 是否与展开模型自洽 |
| --- | --- | --- |
| A. 单标量 | 只有 `p(t)` | ✅ 自洽，但**不能**同音重复 |
| B. 单曲线多泛函 | `γ(t)` + `p(t)`、`a(t)` | ✅ 自洽（本文推荐） |
| C. 独立通道 | X 位置直接查表决定音符数/时值 | ❌ 与曲线脱节，应避免 |

方案 C 才是真正的"相悖"：一旦 X 的绝对值直接映射成音符数量（而不是从曲线的形态派生），音乐就不再由这一笔轨迹决定，回到"隐藏参数"的问题上。方案 B 里 X 只通过**极值（形态）**参与，仍然是"画什么得什么"。

### 6.4 对演奏的含义

一条曲线同时被读成三件事（就像一次运弓同时给出音高、发音和力度）：

```text
γ(t) ──π──> p(t) ──Potts 分段──> 音高 / 音长
     └─α──> a(t) ──极值────────> 再触发 / accent
     └─ζ──> z(t) ──取值────────> 力度 / 音色
```

操作者学的不是"三个旋钮"，而是**一种动作同时表达三件事**——这正是弦乐器的掌握方式，也是"掌控感 + 自由度"同时成立的唯一方式。

## 7. 验收

1. 保持 Y 不动、X 来回 3 次 → 同一个音 3 个事件，音高相同，gate 短。
2. Y 快速跨 5 个音级、X 不动 → 1 次跳进，无中间音。
3. Y 慢速跨 5 个音级 → 允许 1–2 个经过音（可控的"滑音"）。
4. 静止不动 → 1 个长音，无额外事件。
5. 同一采集重复编译 → 事件完全一致。
6. 关掉 X 通道时，行为退回当前版本（可 A/B）。

## 9. 复数能不能解决"一条函数承载两件事"

能，但要分清"改变表达"和"增加信息"是两件事。

### 9.1 两个层次

1. **把平面轨迹写成复数**：`ζ(t) = x(t) + i·y(t)`。这不是新东西——我们的光标本来就是平面曲线，只是取了虚部当音高。复数记法带来的工具是：绕数（数环绕）、辐角（方向）、傅里叶描述子（形状签名）。
2. **把"音高 + 发音"写成复数**：`z(t) = p(t) + i·a(t)`。这是把两条实信号打包成一个复信号，数学上完全合法。

### 9.2 复数不增加信息量

一个复数就是两个实数。`z = p + i·a` 里的 `a` 仍然必须来自第二维测量（X 或 Z）。所以 §6.2 的结论不变：

> **一个标量承载不了两个独立自由度；复数是两个标量，不是一个。**

复数改变的是表达方式与可用工具，不是信息上限。

### 9.3 复数真正带来的三样东西

| 工具 | 用途 | 为什么比实数版好 |
| --- | --- | --- |
| **相位 / 绕数** | 数"运弓了几次"：`n = round(Δarg z_b / π)` | 与幅度、速度无关，只数方向翻转，比"极值 + 死区"更稳 |
| **解析信号** `z_b = b + i·H[b] = A·e^{iφ}` | `A(t)` 直接给 accent；`dφ/dt` 给瞬时频率 | 不需要对噪声信号求导 |
| **傅里叶描述子** | 整条平面轨迹的复数频域签名 | 可用于动机匹配："这个形状刚才出现过" |

其中对当前问题最直接的是**绕数计数**：把运弓偏移 `b(t) = cursor_x − 局部均值` 做成解析信号，每绕半圈（π）触发一次再发音。它天然忽略幅度大小，所以"轻轻拉"和"用力拉"都只算一次，而 accent 由 `A(t)` 给出。

### 9.4 边界

- 绕数只在**来回拉锯**时有效；单向拉动没有绕圈，数不出来。那种情况仍要靠方向反转（极值）。
- Hilbert 变换需要带限信号；`b(t)` 的抖动会让相位抖。实践上用 90° 相移 FIR 或短时 FFT，并先做平滑。
- FPGA 上可行：一对 90° 相移 FIR + 相位解缠，资源很小。

### 9.5 建议

先用**实数版**（极值 + 滞回）实现 X 运弓，因为它简单、可回放、好验证；复数版作为第二步增强，用来换更稳的计数，并把傅里叶描述子留给以后的动机匹配。这样每一步都可单独验收，不会一次引入两个新概念。

## 10. 矢量视角：曲线本来就是矢量的

之前说"展开成一条标量函数"是**不准确的表述**：那是"要量化的目标"，不是曲线本身。正确的对象是：

```text
γ: [t0, t1] → R³                     曲线是矢量值函数，不是标量
F(t) = [p(t), b(t), z(t), v(t)]      音乐特征向量，均为 γ 的标量泛函
p = 音高投影    b = 运弓投影    z = 高度    v = 平滑速度
```

即：**矢量进，标量出**。音符是标量（音高 + 时值），所以最终一定落到标量上；但中间的表达层可以是矢量的。

### 10.1 矢量框架真正买到的三样东西

1. **不依赖"哪根轴是音高"的不变量**：速度、曲率、挠率都是坐标无关的。它们可以用来驱动发音、accent、密度，而不必假设 X 就是运弓、Y 就是音高。
2. **一次三维分段**，而不是三条独立信号各分一次：把 `γ(t)` 用分段线性（DP）拟合，每段是一条三维弦，弦的方向给音高走向、长度给时值、弯曲给发音。
3. **干净的拟合表述**：求旋律曲线 `m(t) = (pitch, gate)` 去拟合手势曲线 `γ(t)`，代价 = 音高误差 + λ·段数 + μ·音乐先验。这与现有 DP 是同一个东西，只是把输入写成矢量。

### 10.2 但高阶不变量现在不可用（实测）

对一段 13266 帧的真实采集，9 帧平滑后：

| 量 | 中位数 | MAD | 说明 |
| --- | --- | --- | --- |
| 速度 | 0.290 | 0.214 | 变化大，但反映真实快慢 |
| **曲率** | 11.9 | **11.1** | p10 = 0，p90 = 143.8，**噪声主导** |

曲率的相对离散度接近 100%，且跨度两个数量级。原因是二阶差分在 200 Hz、10–13 counts 抖动的条件下会放大噪声。

**结论**：曲率/挠率目前不能直接驱动音乐参数。要用它们，必须先做尺度空间平滑（多尺度高斯 + 尺度归一化响应），代价是延迟和对细节的损失。这一步应当单独做、单独验证，不能顺手加进当前的 DP。

### 10.3 建议的特征分层

| 层 | 特征 | 现在可用？ | 用途 |
| --- | --- | --- | --- |
| 零阶 | `p`、`b`、`z` | ✅ | 音高、运弓、力度 |
| 一阶 | `v`（平滑速度） | ✅ | accent、密度 |
| 二阶 | `κ`（曲率）、`τ`（挠率） | ❌ 需先做尺度空间 | 发音层次、转折权重 |

所以当前的实现策略不变：**先用零阶与一阶特征落地**，二阶特征留到有可靠的尺度空间平滑之后。

> **已实现（2026-10-24）**：`intent_features(ticks)` 输出每 tick 的 `pitch / pitch_norm / bow / height / speed / direction / valid / engaged`，写入 `result["intent"]`，诊断附 `intent_summary`。它不产生任何事件，因此启用前后音符序列完全一致（测试覆盖）。`bow` 取 `cursor_x`，`height` 取 `q_z`；`cursor_x` 已加入 128 tick 重采样的插值字段。
