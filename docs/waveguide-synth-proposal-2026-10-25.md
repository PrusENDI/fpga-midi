# 为"画曲线"而生的合成器后端：弓弦波导 + 加法铺底（2026-10-25）

## 1. 为什么现在的后端没有特色

当前实现是 DDS + ADSR + 混音——**任何一块开发板都能做**，评委会问"这和你用手柄弹有什么区别"。  
我们的输入不是按键，是**一条连续曲线**，它天然对应"弓在弦上走"：

```text
Y 高度     → 音高（连续滑动）
X 左右往返 → 弓速与弓压（触发与明暗）
Z 高度     → 离弦距离（阻尼、亮度、气声）
Touch      → 落弓 / 起弓（是否发声）
```

所以后端应该是**被激励的弦**，而不是被触发的振荡器。

## 2. 提议：波导弦（Waveguide）+ 加法铺底

### 2.1 主声部：弓弦波导

```text
excitation  ──→  [ 环形延迟线 N 样本 ] ──┬──→ 输出
   ↑                 ↑                  │
   │            分数延迟（调音）          │
   └── 环路滤波器（阻尼，Z 控制）←────────┘
```

- **激励**：Touch 上升沿注入一段短噪声/脉冲（拨弦）；接触期间持续注入弓噪声（拉弦）。
- **音高**：延迟长度 = 采样率 / 频率，分数延迟用一阶 allpass 插值。
- **阻尼**：环路一阶低通，系数由 Z 决定（越远越暗，模拟离弦）。
- **弓压**：X 往返速度 → 注入噪声幅度与低通亮度。
- **滑音**：延迟长度平滑变化，天然无爆音。

这条路线的独特性：**同一条手势既决定音高，也决定激励方式**——评委看演示时，"画的线就是弓"这一句话就能记住。

### 2.2 铺底声部：加法/波表

Pad、Bass、Arp 仍用现有 DDS 引擎（32 声部里的其余声部），负责和声与节奏。  
这样"物理建模弦"负责主旋律（音色最受关注），"加法"负责铺底（省资源）。

## 3. 资源估算（25K 板）

| 项 | 用量 | 说明 |
| --- | --- | --- |
| 延迟线 | 16 声部 × 1024 × 16 bit = 32 KB | 覆盖 47 Hz 以上；低音另用 DDS |
| 环路低通 + allpass | 每声部 2 个乘法（时分复用） | 16 声部 × 2 = 32 乘法/样本 |
| 加法声部 | 16 × 2 算子 = 32 算子 | 复用现有 DDS 流水 |
| 总计算子 | 16 弦 × 2 + 32 = 64 | 满足 ≥32 口径 |

## 4. 与评分口径的对应

| 要求 | 对应 |
| --- | --- |
| 复音 ≥32 | 16 波导弦 + 16 加法声部（每个 2 算子）= 64 振荡器 |
| 物理建模单元 | 16 条并联弦（题目扩展项明确把"并联弦/模态单元"列为合规统计） |
| ≥3 维表情 | 弓速（X）、阻尼（Z）、滑音（延迟调制） |
| ≥2 音色 | 弓弦（波导）/ 加法（DDS） |
| ≤5 ms 延迟 | 激励到出声 1 个样本周期 + 环路一次（≤1 ms） |

## 5. 与现有代码的接缝

- PC 参考引擎：新增 `waveguide.py`（同定点、同结构），与 `synth_reference.py` 并列；
- RTL：新增 `waveguide_voice.sv`（延迟线 + 低通 + allpass），与 `voice_engine_mux` 共用时分复用骨架；
- 事件表不变：`note_on` 表示落弓，`duration` 表示弓长，`velocity` 表示弓压。

## 6. 风险与降级

| 风险 | 降级 |
| --- | --- |
| 分数延迟调音不准（音准偏差） | 先用整数延迟 + 高采样率（96 kHz 内部）降低量化误差 |
| 延迟线 BRAM 不够 | 弦声部减到 8 条，其余用加法 |
| 环路不稳定（自激） | 环路增益固定 < 0.98，加限幅 |

## 7. 建议的落地顺序

1. PC 上先做 `waveguide.py`，用现有采集试听，确认"像弦"；
2. 再写 RTL（延迟线用 BRAM，低通/allpass 定点）；
3. 最后把 16 条弦与 16 个加法声部混音。
