# Lead 映射分析报告：曲线 → 音高 → 音符（2026-10-22）

版本：2026-10-22  
范围：回答两个问题——**抬手重新吸附后的音频断点**、以及**曲线与旋律的映射为什么不明了**。  
实现：[tools/synthwave_loop.py](../tools/synthwave_loop.py)、[pc_receiver/synthwave_ui.py](../pc_receiver/synthwave_ui.py)

## 1. 结论先行

1. **位置 → 音高是连续的**，而且是线性的：手的高度直接对应半音，`2498 counts = 1 个半音`。
2. **音高 → 音符是事件驱动的**：只有在 `move / hold / turn / apex / valley / release` 这些锚点上才出音，两点之间**不出音**。
3. 因此**曲线的形状决定音符数量，而不是曲线的高度**。一条从最低到最高的直线斜坡，6 秒只产生 **2 个音**（起点与终点）。
4. 抬手会生成一段 **70 tick（约 10.5 秒）的 rest**，同时前后两个音相差 10 个半音。这就是"断点"与"接不上"的来源。
5. 当前渲染器忽略 rest 事件，所以实际听到的是"一个很长的音 + 结尾一个大跳"，而不是静音——这与"音频不连续"的体感一致：**旋律停住了**。

## 2. 映射链（从上到下逐段量化）

```text
① 手的高度 y（原始 counts）
      ↓  CURSOR_Y_RANGE = 32768 ± 65535·0.648/2 = (11534.66, 54001.34)
② cursor_y ∈ [0, 1]                     线性，跨度 42466.68 counts
      ↓  cursor += alpha(z)·(target − cursor)，α ∈ [0.12, 1.0]
③ b_abs = cursor_y
      ↓  raw = 55 + b_abs × 17            G3=55 … C5=72
④ raw_target_midi ∈ [55, 72]
      ↓  带滞回量化到 A 小调五声 [55,57,60,62,64,67,69,72]
⑤ note
```

### 2.1 换算表（低 Z、α≈1 时）

| 手的高度 y | cursor_y | raw_target | 量化后的音 |
| --- | --- | --- | --- |
| 11535 | 0.000 | 55.00 | G3 (55) |
| 18000 | 0.152 | 57.59 | A3 (57) |
| 25000 | 0.317 | 60.39 | C4 (60) |
| 32768 | 0.500 | 63.50 | E4 (64) |
| 40000 | 0.670 | 66.39 | G4 (67) |
| 47000 | 0.835 | 69.19 | A4 (69) |
| 54001 | 1.000 | 72.00 | C5 (72) |

由此可得几个直观量：

```text
1 个半音   = 42466.68 / 17 ≈ 2498 counts
1 个画布像素 ≈ 107 counts ≈ 0.043 半音   （绘图区约 398 px）
量化滞回    = 0.10 半音 ≈ 250 counts
```

**这条链本身是清楚的、线性的、可预测的。** 问题不在①–③，而在④–⑤之后"什么时候出音"。

## 3. 音符是怎么产生的（这才是"不明了"的根源）

`compile_lead` 不按帧出音，它先做地标，再在地标上取音：

```text
resample_to_ticks（128 tick）
→ extract_landmarks：move / hold / turn / apex / valley / rest / release
→ 选择锚点：相邻不足 4 tick 的合并或替换
→ 每个锚点一个音，duration = 到下一个锚点
```

于是：

- **`turn`（方向反转）出音**——所以你画折线、来回摆，音符就多；
- **`apex` / `valley`（局部极值）出音**——拱顶、谷底；
- **`hold`（停住 ≥2 tick）出音**——但只取一段的中点；
- **持续同向移动（`move`）不出音**，只标一个起点；
- 直线斜坡没有任何方向反转、没有极值、没有停留 → **只有起点和终点两个锚点**。

### 3.1 实测一：直线斜坡只出 2 个音

输入：6 秒内 y 从 12000 线性升到 53000（跨越整个音域），低 Z，X 居中。

```text
notes: 2
  tick   1 note 55  raw 55.29
  tick 127 note 72  raw 71.57
```

也就是说，**你把手从最低一路抬到最高，只听到两个音**。这解释了"曲线和旋律对不上"：中间 6 秒的连续升高，在音符层完全不存在。

### 3.2 实测二：抬手的断点

输入：第一段上升 → 抬手 0.5 秒（z 升到 42000，手同时漂移）→ 落下继续上升。

```text
note_on tick   1 dur 126 note 57
rest    tick  57 dur  70
note_on tick 127 dur   2 note 67
```

三个问题同时出现：

1. **rest 长达 70 tick**（约 10.5 秒，占 8 小节的 55%）。它来自"抬起期间的帧被判无效"，而无效段在 `resample_to_ticks` 里被扩展成 rest。
2. **rest 与 note 重叠**：第一个音 `dur=126` 覆盖 1–127，rest 覆盖 57–127，两者时间上重叠。当前渲染器只看 `note_on`，所以这个 rest 不发声；但它一旦被外部合成器尊重，就会把音切断。
3. **接合处的音高跳 10 个半音**（57 → 67）：因为接合帧吸附到新手位，音高随之跳到新位置。

## 4. 断点的三种成因（分开处理）

| 成因 | 现状 | 可选项 |
| --- | --- | --- |
| A. 抬起段被判无效 → rest | 生成 70 tick rest | ① 不产生 rest，改为延长前一音的 gate；② 只有离开超过 1 小节才休止 |
| B. rest 与音重叠 | `duration` 到下一锚点，未截断 | 音符时长必须截到下一个事件（含 rest）之前 |
| C. 接合跳变 | 吸附后直接成为新音 | ① 接合后首个音做忽略（已做一半）；② 允许 glide 过渡 |

## 5. 为什么"映射不明了"——三个可操作的改法

### 5.1 让连续移动也出音（最关键）

当前只有"转折"出音。要让曲线高度真正变成旋律，需要**轮廓采样**：在持续 `MOVE` 期间，每当量化音级比上一个音高出/低于 1 个音级、且距上一音 ≥ 2–4 tick，就出一个音。

```text
while state == MOVE:
    if 量化音级 != 上一音 且 tick - last_tick >= min_gap:
        出新音
```

代价：音符数量上升（一条斜坡可能出 5–8 个音），需要配合每小节上限（规范要求 ≤8 onset/小节、全曲 ≤16）。这是**音乐结果的变化**，必须同步修改 Lead 设计文档 §8.4 与主规范。

### 5.2 抬手不再产生 rest

把"抬起"与"无效帧"分开：

- 抬起 = 用户主动松手 → 结束当前 gate，触发 release tail（不写 rest 事件）；
- 无效帧（丢帧、饱和）= 数据问题 → 才写 rest。

这样抬手后音频是"一个自然的释放尾音"，而不是 10 秒静音。

### 5.3 音符时长必须被下一事件截断

任何音的 `duration` 不应越过下一个 `note_on` 或 `rest` 的起点。当前 126 tick 的长音越过 rest 属于实现缺陷，应修。

## 6. 建议的处理顺序

1. **修 B（时长截断）**：纯 bug，不改变音乐设计，先做。
2. **修 A（抬手 → release 而非 rest）**：消除断点，符合演奏直觉。
3. **加 5.1 轮廓采样**：让曲线高度直接驱动旋律；这会显著增加音符密度，需要你确认密度上限（建议起步：每 ≥4 tick 允许一个新音，每小节 ≤8）。

前两项做完，抬手后的音频就是连续的；第三项做完，"画什么形状出什么旋律"才会稳定可预期。

## 6.1 实施结果（2026-10-22，第 1、2 项已完成）

改动：`_apply_cursor_layer` 为每帧增加 `cursor_lift` 标记，`resample_to_ticks` 把它传递到 tick，`extract_landmarks` 只在**非抬手**的无效段生成 rest；`compile_lead` 在事件排序后把每个音的时长截到下一个事件之前。

同一段合成采集（上升 → 抬手 0.5 s → 继续上升）的前后对比：

```text
改前：note_on tick 1 dur 126 | rest tick 57 dur 70 | note_on tick 127
改后：note_on tick 1 dur 126 | note_on tick 127
```

70 tick 的 rest 消失，音频在抬手期间由前一个音持续，不再出现空洞。

真实的丢帧（非抬手）仍会生成 rest，且音被截断，不再与其重叠：

```text
note_on tick 1 dur 41 | note_on tick 42 dur 1 | rest tick 43 dur 43 | note_on tick 86 …
```

**遗留的听感问题**：抬手期间没有新事件，所以前一个音会一直持续到下一个锚点——在当前只有"转折/极值"出音的规则下，这会表现为一个很长的长音（上例 126 tick）。这不是断点，但也不是旋律。真正的解决要靠第 3 项轮廓采样，把长音拆成随高度变化的音符。

## 7. 验收方式

用同一段采集回放，检查：

- 一条从低到高的直线斜坡：音符数 ≥5，且音高单调不回头；
- 一次抬手：不出现 ≥4 tick 的 rest，前一音有明确的 release；
- 任何音符的 duration 不超过下一个事件；
- 抬手的接合处不产生超过 7 个半音的跳进（否则触发 glide 或吸附首音忽略）。
