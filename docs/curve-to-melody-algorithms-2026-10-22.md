# 曲线 → 旋律：高级算法评估（2026-10-22）

版本：2026-10-22  
问题：在当前的 3D 追踪条件下，有没有比"地标锚点"更高级的办法，把曲线的几何要素可靠地变成旋律要素？是否值得从频域/时域解构？  
关联：[Lead 映射分析报告](lead-mapping-report-2026-10-22.md)、[Lead 曲线意图提纯设计](pc-lead-intent-purification-design-2026-10-19.md)

## 1. 先钉住约束

任何方案都必须活在这组条件下，否则讨论没有意义：

| 约束 | 数值 / 事实 |
| --- | --- |
| 采样 | 200 Hz，3 轴，约 5 ms 一帧 |
| 噪声 | 横向抖动 10–13 counts（满量程 0.02%） |
| 音高分辨率 | 2498 counts / 半音；画布 1 px ≈ 0.043 半音 |
| 音乐网格 | 128 tick / 8 小节；100 BPM 下 1 tick = 150 ms |
| 当前最小音间隔 | 4 tick = 600 ms |
| 确定性 | 同一采集必须得到同一结果（设计文档硬约束） |
| 可解释 | 每个音必须能回指来源；禁止黑箱重写旋律 |
| FPGA 目标 | 有界、定点、小内存，后续要能移植 |

这七条决定了：**复杂模型不是不能用，而是必须"可审计、可离线、有界"**。任何需要训练数据或大量浮点的方案，只能留在 PC 黄金模型里。

## 2. 现在的做法缺什么

当前是"地标 → 锚点 → 音"：只在 `turn / apex / valley / hold` 出音。实测一条跨越全音域的直线斜坡只出 **2 个音**。

缺的不是精度，而是**"持续运动也应该产生音符"这条通路**。所以真正的问题不是"要不要更高级的模型"，而是"用什么规则把连续位移离散成音"。

## 3. 算法族评估

| 方法 | 它买到什么 | 成本 | 适配度 | 结论 |
| --- | --- | --- | --- | --- |
| **电平穿越（level crossing）** | 每跨过一个音级出一个音，把"走了多远"直接变成"出几个音" | 极低，~30 行 | ★★★★★ | **首选** |
| **尺度空间 / 小波模极大** | 自动选尺度：大动作找大转折，小动作找小转折，不用手调阈值 | 中，~100 行 | ★★★★☆ | 次选，替换固定阈值 |
| **弧长等距采样** | 音符按"沿曲线等距"分布，与手速解耦 | 低 | ★★★★☆ | 与电平穿越互补 |
| **EMD / 希尔伯特-黄** | 把曲线拆成"慢趋势 + 快抖动"，自适应分离意图与噪声 | 中，需迭代筛分 | ★★★☆☆ | 诊断价值 > 生成价值 |
| **STFT / 小波时频** | 测手势周期、节奏谱、抖振频率 | 低 | ★★★☆☆ | 只用于节奏对齐与噪声估计，**不能决定音高** |
| **卡尔曼 / IMM** | 状态估计 + 模式切换（静/慢/快），给出预测与置信度 | 中 | ★★★☆☆ | 用于平滑与置信度，不解决离散化 |
| **HSMM + 有界 Viterbi** | 全局最优的音符序列，带时值先验 | 高 | ★★☆☆☆ | 设计文档里的 Advanced，等 Baseline 稳了再说 |
| **DTW / Parsons code 动机匹配** | 识别"这个形状刚才出现过"，用于动机重复 | 中 | ★★★☆☆ | 句法层，晚于离散化 |
| **端到端神经网络** | 理论上能学"手势→旋律" | 高 | ★☆☆☆☆ | 没有配对数据；不可解释；不可移植 |

## 4. 首选：电平穿越（这正是"高级"但可解释的解法）

### 4.1 规则

```text
p = b_abs × (len(P) − 1)          # 连续音级坐标，P 为固定五声音级表
i = round(p)
if |p − last_p| > hysteresis 且 i ≠ last_i 且 tick − last_tick ≥ min_gap:
    在 i 上出一个音
```

也就是：**光标每跨过一个音级边界，就出一个音**。方向决定上行/下行，跨越的次数决定音符数量。

### 4.2 为什么它比"更复杂的模型"更合适

- 它把"几何位移"和"音符数量"直接联系起来：走 3 个音级就是 3 个音。这是用户"画什么听到什么"的直觉。
- 完全确定性、可回放、可解释（每个音都对应一次音级穿越）。
- 计算量极小，FPGA 也能跑（比较器 + 计数器）。
- 与现有地标机制**不冲突**：`turn/apex/valley` 仍然保留，电平穿越补上"持续移动"。

### 4.3 参数建议

```text
min_gap      = 4 tick（600 ms，与现有最小间隔一致）
hysteresis   = 0.25 音级（防止在边界抖动出双音）
密度上限     = 每小节 8 / 全曲 24（需同步改主规范 §8.4）
```

### 4.4 预期效果（按当前数据推算）

- 6 秒全音域斜坡：17 个音级 → 受 4 tick 间隔限制，约 **8–10 个音**（现在 2 个）。
- 小幅抖动（±2 counts）：远小于 0.25 音级，不产生音。
- 抬手：光标冻结，不穿越音级，不产生音；前一个音持续。

## 5. 次选：尺度空间地标（替换固定阈值）

现在的阈值是常数（`b` 差 > 0.012、`db` > 0.0015、`speed < 0.002`），对不同幅度的手势不敏感。尺度空间的做法：

```text
对 b(s) 做高斯平滑，σ 从 1 到 σ_max 递增
在每一尺度取二阶导数的过零点（拐点）与极值
用"尺度归一化响应"选每个地标的特征尺度 σ*
σ* 大的地标 = 大转折（结构），σ* 小的 = 小转折（装饰）
```

好处：一次运转就同时得到"结构点"和"装饰点"，不需要为不同手势改阈值，而且**地标自带重要性**，可直接映射到音符权重（大转折 → 长音/重音，小转折 → 装饰）。

代价：需要在 128 tick 上做多尺度平滑，PC 上几十毫秒，FPGA 可用 3–4 个离散尺度近似。

## 6. 频域/时域解构：能做和不能做

**能做的：**

- **节奏谱**：对速度 `|dq/dt|` 做 STFT，找主频 → 判断手势的周期性，用于把 onset 吸附到最近的拍。这是"节奏由时间戳决定"的辅助，不改变音高。
- **抖动谱**：对静止段做谱分析，测出环境噪声的主频，用于自适应死区（比固定 0.0004 更稳）。
- **EMD 分解**：把 `b(t)` 拆成 2–3 个分量，慢分量做轮廓、快分量算 confidence。比固定 IIR 更能适应不同速度的手势。

**不能做的：**

- **用频谱分量直接决定音高**。把 `b(t)` 的谱峰映射成音级，会让"同一高度"因速度不同而变音，直接违反固定 PitchSpace。
- **FFT 全局分析**：6 秒的乐句做 FFT 会丢失时间位置，无法定位音符。
- **把空间频率当节奏**：设计文档明确禁止用空间距离重排时间轴。

结论：频域工具适合做**分析、阈值自适应、节奏对齐**，不适合做**音高分配**。

## 7. 建议路线

| 阶段 | 内容 | 改动性质 | 价值 |
| --- | --- | --- | --- |
| 1 | **电平穿越** | 生成规则 | 解决"直线不出音"，曲线高度直接变旋律 |
| 2 | **尺度空间地标** | 阈值替换 | 不同幅度的手势都能得到合理的地标 |
| 3 | **弧长等距补充** | 生成规则 | 速度变化时音符分布仍均匀 |
| 4 | **EMD 诊断 + 自适应阈值** | 滤波/诊断 | 噪声与意图分离更稳，参数不再手调 |
| 5 | HSMM + 有界 Viterbi | 句法层 | 动机、半终止、高潮的全局整理 |

1 和 2 是"让映射成立"，3–5 是"让旋律好听"。**在 1 落地之前，任何更高级的模型都只是在给一个没有音符的序列做优化。**

## 8. 验收指标

- 全音域斜坡：音符数 8–10，音高单调不回头；
- 同一高度重复经过：音名一致（除滞回边界 ±0.25 音级）；
- 抖动段（±5 counts 往复 2 秒）：0 个新音；
- 抬手前后：无 rest，长音连续；
- 同一采集重复编译：事件表逐字节一致；
- 每小节 onset ≤8、全曲 ≤24（待确认）。
