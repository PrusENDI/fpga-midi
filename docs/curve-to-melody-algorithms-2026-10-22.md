# 曲线 → 旋律：高级算法评估（2026-10-22）

版本：2026-10-22  
问题：在当前的 3D 追踪条件下，有没有比"地标锚点"更高级的办法，把曲线的几何要素可靠地变成旋律要素？是否值得从频域/时域解构？  
关联：[Lead 映射分析报告](lead-mapping-report-2026-10-22.md)、[Lead 曲线意图提纯设计](pc-lead-intent-purification-design-2026-10-19.md)

## 0. 设计前提（用户 2026-10-22 明确）

> 曲线的几何要素主要表达**意向与情绪**；整条曲线无法像钢琴键盘那样输出离散音符；而特雷门琴式的连续演奏又难以控制。因此用**特定曲风的算法去拟合曲线**。

这条前提决定了问题的性质：

- 不是**转录**（transcription）：不要求"每个手部位置对应一个音"，那是键盘/特雷门；
- 也不是**自由映射**（theremin）：连续音高难以稳定控制；
- 而是**拟合**（style fitting）：曲线提供表达意图，Synthwave 风格提供离散化规则。

换句话说，系统要回答的不是"这个位置是哪个音"，而是"**这条曲线在 Synthwave 里应该被唱成什么**"。这更接近"跟着哼唱写谱"，而不是"把手当琴键"。

由此得到三层责任划分：

| 层 | 输入 | 输出 | 谁负责"离散化" |
| --- | --- | --- | --- |
| 表达提取 | 光标轨迹 + Z + 时间 | 意图特征（方向、能量、跨度、停留、释放、高潮） | 不做离散化 |
| 风格拟合 | 意图特征 + tick + 和弦 | 音符候选（音级、时值、力度） | **风格层** |
| 演奏与渲染 | 音符候选 | EventTable → 音频 | 不改变音符 |

关键含义：**离散化规则属于风格，不属于几何**。同一个手势在 Synthwave 和别的曲风下可以拟合出不同旋律，这是特性而不是缺陷；但同一曲风、同一采集必须确定。

## 1. 先钉住约束

任何方案都必须活在这组条件下，否则讨论没有意义：

| 约束 | 数值 / 事实 |
| --- | --- |
| 采样 | 200 Hz，3 轴，约 5 ms 一帧 |
| 噪声 | 横向抖动 10–13 counts（满量程 0.02%） |
| 音高分辨率 | 2498 counts / 半音；画布 1 px ≈ 0.043 半音 |
| 音乐网格 | 128 tick / 8 小节；100 BPM 下 1 tick = 150 ms |
| 当前最小音间隔 | 4 tick = 600 ms |
| 确定性 | 同一采集必须得到同一结果（设计文档硬约束） |
| 可解释 | 每个音必须能回指来源；禁止黑箱重写旋律 |
| FPGA 目标 | 有界、定点、小内存，后续要能移植 |

这七条决定了：**复杂模型不是不能用，而是必须"可审计、可离线、有界"**。任何需要训练数据或大量浮点的方案，只能留在 PC 黄金模型里。

## 2. 现在的做法缺什么

当前是"地标 → 锚点 → 音"：只在 `turn / apex / valley / hold` 出音。实测一条跨越全音域的直线斜坡只出 **2 个音**。

缺的不是精度，而是**"持续运动也应该产生音符"这条通路**。所以真正的问题不是"要不要更高级的模型"，而是"用什么规则把连续位移离散成音"。

## 3. 算法族评估

| 方法 | 它买到什么 | 成本 | 适配度 | 结论 |
| --- | --- | --- | --- | --- |
| **电平穿越（level crossing）** | 每跨过一个音级出一个音，把"走了多远"直接变成"出几个音" | 极低，~30 行 | ★★★★★ | **首选** |
| **尺度空间 / 小波模极大** | 自动选尺度：大动作找大转折，小动作找小转折，不用手调阈值 | 中，~100 行 | ★★★★☆ | 次选，替换固定阈值 |
| **弧长等距采样** | 音符按"沿曲线等距"分布，与手速解耦 | 低 | ★★★★☆ | 与电平穿越互补 |
| **EMD / 希尔伯特-黄** | 把曲线拆成"慢趋势 + 快抖动"，自适应分离意图与噪声 | 中，需迭代筛分 | ★★★☆☆ | 诊断价值 > 生成价值 |
| **STFT / 小波时频** | 测手势周期、节奏谱、抖振频率 | 低 | ★★★☆☆ | 只用于节奏对齐与噪声估计，**不能决定音高** |
| **卡尔曼 / IMM** | 状态估计 + 模式切换（静/慢/快），给出预测与置信度 | 中 | ★★★☆☆ | 用于平滑与置信度，不解决离散化 |
| **HSMM + 有界 Viterbi** | 全局最优的音符序列，带时值先验 | 高 | ★★☆☆☆ | 设计文档里的 Advanced，等 Baseline 稳了再说 |
| **DTW / Parsons code 动机匹配** | 识别"这个形状刚才出现过"，用于动机重复 | 中 | ★★★☆☆ | 句法层，晚于离散化 |
| **端到端神经网络** | 理论上能学"手势→旋律" | 高 | ★☆☆☆☆ | 没有配对数据；不可解释；不可移植 |

## 4. 首选：电平穿越（这正是"高级"但可解释的解法）

### 4.1 规则

```text
p = b_abs × (len(P) − 1)          # 连续音级坐标，P 为固定五声音级表
i = round(p)
if |p − last_p| > hysteresis 且 i ≠ last_i 且 tick − last_tick ≥ min_gap:
    在 i 上出一个音
```

也就是：**光标每跨过一个音级边界，就出一个音**。方向决定上行/下行，跨越的次数决定音符数量。

### 4.2 为什么它比"更复杂的模型"更合适

- 它把"几何位移"和"音符数量"直接联系起来：走 3 个音级就是 3 个音。这是用户"画什么听到什么"的直觉。
- 完全确定性、可回放、可解释（每个音都对应一次音级穿越）。
- 计算量极小，FPGA 也能跑（比较器 + 计数器）。
- 与现有地标机制**不冲突**：`turn/apex/valley` 仍然保留，电平穿越补上"持续移动"。

### 4.3 参数建议

```text
min_gap      = 4 tick（600 ms，与现有最小间隔一致）
hysteresis   = 0.25 音级（防止在边界抖动出双音）
密度上限     = 每小节 8 / 全曲 24（需同步改主规范 §8.4）
```

### 4.4 预期效果（按当前数据推算）

- 6 秒全音域斜坡：17 个音级 → 受 4 tick 间隔限制，约 **8–10 个音**（现在 2 个）。
- 小幅抖动（±2 counts）：远小于 0.25 音级，不产生音。
- 抬手：光标冻结，不穿越音级，不产生音；前一个音持续。

## 5. 次选：尺度空间地标（替换固定阈值）

现在的阈值是常数（`b` 差 > 0.012、`db` > 0.0015、`speed < 0.002`），对不同幅度的手势不敏感。尺度空间的做法：

```text
对 b(s) 做高斯平滑，σ 从 1 到 σ_max 递增
在每一尺度取二阶导数的过零点（拐点）与极值
用"尺度归一化响应"选每个地标的特征尺度 σ*
σ* 大的地标 = 大转折（结构），σ* 小的 = 小转折（装饰）
```

好处：一次运转就同时得到"结构点"和"装饰点"，不需要为不同手势改阈值，而且**地标自带重要性**，可直接映射到音符权重（大转折 → 长音/重音，小转折 → 装饰）。

代价：需要在 128 tick 上做多尺度平滑，PC 上几十毫秒，FPGA 可用 3–4 个离散尺度近似。

## 6. 频域/时域解构：能做和不能做

**能做的：**

- **节奏谱**：对速度 `|dq/dt|` 做 STFT，找主频 → 判断手势的周期性，用于把 onset 吸附到最近的拍。这是"节奏由时间戳决定"的辅助，不改变音高。
- **抖动谱**：对静止段做谱分析，测出环境噪声的主频，用于自适应死区（比固定 0.0004 更稳）。
- **EMD 分解**：把 `b(t)` 拆成 2–3 个分量，慢分量做轮廓、快分量算 confidence。比固定 IIR 更能适应不同速度的手势。

**不能做的：**

- **用频谱分量直接决定音高**。把 `b(t)` 的谱峰映射成音级，会让"同一高度"因速度不同而变音，直接违反固定 PitchSpace。
- **FFT 全局分析**：6 秒的乐句做 FFT 会丢失时间位置，无法定位音符。
- **把空间频率当节奏**：设计文档明确禁止用空间距离重排时间轴。

结论：频域工具适合做**分析、阈值自适应、节奏对齐**，不适合做**音高分配**。

## 7. 建议路线

| 阶段 | 内容 | 改动性质 | 价值 |
| --- | --- | --- | --- |
| 1 | **电平穿越** | 生成规则 | 解决"直线不出音"，曲线高度直接变旋律 |
| 2 | **尺度空间地标** | 阈值替换 | 不同幅度的手势都能得到合理的地标 |
| 3 | **弧长等距补充** | 生成规则 | 速度变化时音符分布仍均匀 |
| 4 | **EMD 诊断 + 自适应阈值** | 滤波/诊断 | 噪声与意图分离更稳，参数不再手调 |
| 5 | HSMM + 有界 Viterbi | 句法层 | 动机、半终止、高潮的全局整理 |

1 和 2 是"让映射成立"，3–5 是"让旋律好听"。**在 1 落地之前，任何更高级的模型都只是在给一个没有音符的序列做优化。**

## 8. 验收指标

- 全音域斜坡：音符数 8–10，音高单调不回头；
- 同一高度重复经过：音名一致（除滞回边界 ±0.25 音级）；
- 抖动段（±5 counts 往复 2 秒）：0 个新音；
- 抬手前后：无 rest，长音连续；
- 同一采集重复编译：事件表逐字节一致；
- 每小节 onset ≤8、全曲 ≤24（待确认）。

## 9. 三层架构的具体形态

### 9.1 表达提取：意图特征（每个乐句段）

对每一段（两个结构地标之间，或每 4–8 tick 一个窗口）计算以下量，全部是低维、可解释的标量：

```text
direction      sign(db/dt) 的稳健符号
slope          |db/dt| 的中位数（音级/tick）
span           该段的 |Δb|（跨了几个音级）
energy         |dq/dt| 与 Z proximity 的合成
dwell          速度低于阈值的持续时间
release        结束方式：lift / rest / turn
curvature      平均曲率（决定装饰密度）
climax         该段是否为全局最高点附近
confidence     有效帧比例 × 地标稳定性
```

这些量不产生音符，只描述"这一笔想干什么"。

### 9.2 风格拟合：Synthwave 的离散化规则

风格层拿意图特征 + tick + 当前和弦，按固定规则产生音符候选：

```text
① 轮廓跟随：span ≥ 1 音级时按电平穿越出音（0.25 音级滞回，4 tick 下限）
② 强拍约束：onset 落在强拍时优先当前和弦音，弱拍允许五声经过音
③ 时值：dwell 长 → 长音；span 大且 slope 高 → 短音 + 跳进
④ 力度：energy 与 proximity 决定 velocity
⑤ 密度：每小节 ≤8、全曲 ≤24（待确认），超限先删低 confidence 装饰
⑥ 保留结构：climax 段禁止被密度裁剪删除
```

注意①–⑥ 都是**风格规则**，不是几何定理。换曲风时替换的是这一层。

### 9.3 为什么这不是"特雷门琴"

特雷门把连续位置直接变成连续音高，人是闭环控制器，所以难稳。这里有三道离散化闸门，都由风格提供：

1. 固定五声音级表（不允许连续音高）；
2. 最小音间隔 4 tick（不允许无限细分）；
3. 强拍优先和弦音（不允许随意半音）。

曲线只决定"往哪走、走多远、多用力"，**不决定具体音名**。这正是"用风格拟合曲线"与"把曲线当琴键"的区别。

### 9.4 与现有代码的对应

| 层 | 现状 | 改造 |
| --- | --- | --- |
| 表达提取 | 没有独立层；`extract_landmarks` 直接从几何出音 | 新增 `intent_features()`：段级特征，不产生事件 |
| 风格拟合 | `compile_lead` 里硬编码"锚点即音符" | 改为"特征 + 和弦 → 候选"，电平穿越放在这里 |
| 演奏渲染 | `render_loop` | 不变 |

改造的核心是把"几何 → 音符"拆成"几何 → 意图 → 音符"，让中间层可检查、可替换、可移植。FPGA 版本只需要实现固定点版本的 `intent_features` 与有限候选的风格拟合，不需要通用几何。

## 10. 这套架构适合"高自由度合成器"吗

结论：**适合做高自由度的演奏控制器，不适合做高自由度的合成器本体——这是刻意的取舍，不是能力不足。**

### 10.1 为什么

这套系统的全部价值来自"把连续曲线变成**可辨认**的乐句"。可辨认来自约束：固定音阶、固定音域、固定网格、固定句法。把约束全部拆掉，得到的不是更自由的乐器，而是"带额外步骤的特雷门"——连续、难控、无法重复。

换句话说：**自由度和可辨识度在这里是同一个旋钮的两端。**

### 10.2 哪些维度该开放，哪些必须锁

| 维度 | 现状 | 该不该开放 | 代价 |
| --- | --- | --- | --- |
| 音色 / 滤波 / FX / 空间 | 单个 LeadPatch | ✅ 应开放 | 低，只影响渲染层 |
| 表现强度（Z→力度/亮度） | 固定曲线 | ✅ 应开放 | 低 |
| 风格（离散化规则） | 单一 Synthwave | ✅ 应开放为**多风格** | 中，每种风格一套候选规则与验收 |
| 手势映射参数（α、死区、阈值） | 常量 | ✅ 可开放为 profile | 低，已有参数化基础 |
| 层数/多手 | 单轨迹 | ⚠️ 后续 | 高，需要分离与仲裁 |
| 音阶/调式 | 固定 A 小调五声 | ⚠️ 录制前可选 | 中，需重建 PitchSpace 并重测 |
| 音域/中心 | 固定 G3–C5 | ⚠️ 录制前可选 | 中，同上 |
| 拍号/BPM/和声进行 | 4/4 100 BPM Am–F–C–G | ⚠️ 录制前可选 | 中，网格与和弦表要参数化 |
| Loop 长度 | 固定 8 小节 | ⚠️ 后续 | 高，句法与密度规则都要跟着变 |
| 实时改音符/逐音编辑 | 无 | ❌ 不属于本产品 | 那是 DAW 的职责 |

### 10.3 三种"自由度"要分开说

1. **结构自由度**（音阶、拍号、和声、Loop 长度）——建议**在录制前锁定**，不作为演奏中可调参数。演奏中改结构会让同一手势产生不同结果，破坏可学习性。
2. **表达自由度**（音色、力度曲线、FX、映射灵敏度）——**应当开放**，因为它不改变"哪个音"，只改变"怎么响"。
3. **风格自由度**（离散化规则本身）——**最值得投入的方向**。把风格做成可插拔模块，比在单一风格里堆参数更能扩展表现力，也让每套规则仍可验证。

### 10.4 如果确实要"万能"

产品上更干净的做法是**把本系统降级为控制器**：输出 MIDI / MPE（每音带 pitch bend、pressure、timbre），让外部合成器承担音色与复音自由度。这时本系统只需保证"离散化规则可解释 + 事件带表达量"，自由度问题交给下游。

当前的 EventTable 已经包含 `velocity / accent / glide / pitch_mod / timbre_mod`，改造成 MPE 输出的成本主要是协议层，而不是算法层。

### 10.5 建议的产品定位

> 不是"什么都能做的合成器"，而是"**能把一条曲线稳定唱成 Synthwave 的演奏器**"。

在这个定位下，自由度应该花在：风格库、音色与空间、表达映射、以及后期（Intent/Song 候选、comping）。而不是花在拆掉音阶和网格——那会把产品变回一个难以控制的连续乐器。
