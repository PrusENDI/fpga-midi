# MGC3130 音频前输入反馈设计讨论

日期：2026-10-19

状态：讨论记录，尚未实现或完成实机验证。本文保存本次 LIVE/Synthwave 探索中的输入反馈思路，不作为已经冻结的实现规格，也不替代其他 Ambient/CAPTURE & LOOP 讨论文档。

## 1. 讨论范围与用户意图

用户提出的“闭环”限定在音频生成之前：从 MGC3130 原始 XYZ，到稳定的演奏控制参数，再到参数接受状态的反馈。

音频波形、扬声器输出和物理执行器不参与该反馈；本次也不讨论特雷门琴模式。Synthwave 探索中的参数分工为：

- X：选择根音或和弦级数。
- Y：选择节奏型。
- Z：控制主奏力度；是否同时承担主奏门控及具体策略，留待设计确认。

和弦槽位数量、节奏型数量、调式、BPM、声部数量和切换边界均未最终冻结。

## 2. 建议的数据流

```text
MGC3130 原始 XYZ、有效标志、报告时间戳
    -> 有效性检查、异常点处理、滤波
    -> 位置与动作估计
    -> 候选参数生成、稳定确认
    -> 参数提交 / 节拍同步
    -> 已生效的和弦、节奏、力度和 gate
         |                         |
         | 反馈到后续控制决策       -> 合成器 -> 音频
         +-------------------------
```

严格来说，这包含“带反馈的位置估计”和“带接受确认的控制状态机”，不是对真实手部位置的物理伺服闭环。

## 3. 第一层反馈：位置与动作估计

每次有效报告到来时，用当前测量与上一次估计计算残差：

```text
residual = measured_xyz - estimated_xyz
```

根据偏差幅度、持续时间和动作状态，决定估计值如何更新：

- 小幅波动：进入死区或弱跟随，避免静止噪声变成控制动作。
- 持续缓慢移动：平滑跟随，保留操作者的移动意图。
- 短暂大跳变：降低可信度或等待后续报告确认，不立即切换参数。
- 连续且可信的快速移动：允许提高跟随速度，避免过度滤波造成拖滞。
- 无效报告或失联：进入明确的保持、超时和释放流程，不能无限保持未知输入状态。

算法可考虑一阶低通、带死区的自适应平滑或有限窗口估计；具体方法、门限和时延需由真实数据决定。不能把真实快速动作一律当成离群点。

这一层不能修复传感器电场非线性，也不能证明估计位置就是实际物理位置。硬件基线校准、应用坐标参考和输入滤波应分别处理；不通过每帧调用设备校准命令实现反馈。

## 4. 第二层反馈：已生效的控制状态

候选参数与已经接受并生效的参数比较，而不是把每一帧直接转成音符事件。

以 X 和弦选择为例：

```text
estimated_x
    -> candidate_chord
    -> 滞回与稳定确认
    -> pending_chord
    -> 安全音乐边界提交
    -> active_chord
         -> 反馈给候选比较与去重
```

- 候选等于 active 状态时，不重复提交同一个变化。
- 候选稳定但尚未到提交边界时，只更新 pending 状态。
- 在实际提交时才更新 active 状态；排入队列不等于已经生效。
- 下游暂时不能接受时，保留明确的待提交状态，避免重复交付。
- Y 节奏型使用同类确认机制。下一拍或下一小节切换是可选策略，尚需确认演奏响应速度。
- Z 力度走连续目标通道，经限幅和平滑后更新；它与离散的按下/释放状态分开，不能每帧重触发主奏。
- 若启用 Z gate，按下/释放应独立使用滞回和持续时间确认；失联、STOP 和模式退出需有明确的取消与恢复语义。

控制状态仅约束接受与切换，不应让输入估计被当前和弦强行拉回，从而掩盖真实移动。

## 5. 音频前输出接口的方向

建议输出稳定的控制状态及其变化通知：

```text
active_chord / root
active_rhythm
lead_gain_target
lead_gate（若采用）
input_valid / stale / fault
pending 状态与提交确认（用于握手和诊断）
```

合成器或节奏生成器根据这些参数和音乐时钟产生声音。传感器报告率不直接决定音符触发率。音乐时钟调度的有意琶音，与传感器抖动造成的误触发，应能在诊断中区分。

## 6. 当前故障的证据边界

用户报告：手停在一个位置时，仍听到离散步进或琶音感。

现有检查发现真实采集会话包含 X 音区变化和 Z 阈值跨越；但整段会话包含进入、离开或移动过程，不能把全段统计直接当作持续静止时的抖动证据。当前 mapper 的边界滞回、Z 确认、事件队列同周期入队/出队，以及实际烧录版本，均需要进一步隔离验证。

已有 mapper、mixer、audio path 和顶层仿真通过，只能说明现有测试覆盖范围内的行为成立。队列竞争目前是代码检查发现的风险，临时复现未成功运行，不能宣称已经确认它是听感问题的根因。

因此本设计方向尚不能被宣称“已解决静止步进”。后续需核对实际位流，并记录同一段静止操作的原始 XYZ、估计值、候选/active 参数及 NOTE_ON/OFF/REVOICE 事件。

## 7. 后续验证要求

1. 固定输入和真实静止片段回放时，不重复提交相同和弦、节奏或 gate 边沿。
2. 边界附近小幅往返不会导致 active 状态来回切换；明确跨区移动可以在可接受时延内生效。
3. 单帧离群、短时无效与长时失联各有可观察、可恢复的处理结果。
4. pending 与 active 可分别观测，提交边界和下游接受确认可追踪。
5. Z 力度连续变化不重新触发音符；gate 变化与节奏生成事件可分别计数。
6. 新输入路径与 RECORD/OVERDUB 的存储、Loop tick 和提交语义保持清晰边界。

本次仅记录讨论，不修改 RTL、生成位流或执行烧录。
