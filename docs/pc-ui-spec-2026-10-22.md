## 3. 中栏：画布

绘图区是**正方形 XY 俯视图**，居中，边长 `min(宽-32, 高-32)`；边距只保留 16 px，左右栏和事件表为绘图区让出空间。Lead 的 X/Y 位置直接画在平面上，Z 不再通过等距投影移动光标，而是通过轨迹颜色表达。画布外围使用面板底色，正方形内部才使用绘图区深色填充，避免出现“矩形里套正方形”的视觉层级。

### 3.1 投影

XY 使用统一的单位尺度，Z 使用固定色标：蓝色表示较低 Z，橙色表示较高 Z。`cursor_x/cursor_y` 优先于原始坐标，因为它们是 cursor 模式下真正送入编译器的 XY；其他轨道或编译样本回退到 `q_x/q_y`，最后才使用原始计数。

```text
输入：x, y, z = 归一化坐标（0–1）
screen_x = plot_left + x · plot_width
screen_y = plot_top + (1 - y) · plot_height
轨迹颜色 = lerp(#4f7cff, #ff9f68, z)
```

### 3.2 图元清单

| 图元 | 数据来源 | 颜色 | 样式 |
| --- | --- | --- | --- |
| XY 网格 | 无（装饰） | `#182235` | 0/0.25/0.5/0.75/1.0 五档横纵刻度 |
| 绘图区边框 | 最大化正方形绘图区 | `#1d2740` | 1 px 矩形；外围使用面板底色 |
| X/Y 刻度 | 归一化空间坐标 | `#536078` | 轴旁显示 0.00、0.25、0.50、0.75、1.00，并标注 `X / horizontal`、`Y / pitch` |
| 音级导线 | `DEFAULT_PITCH_SPACE.scale_pitches` 共 8 条 | `#27344d` | 与 XY 轨迹使用同一空间坐标，虚线并标 MIDI 号 |
| 轨迹折线 | `cursor_x` / `cursor_y` / `z_norm` | Z 色标（10 阶） | 2 px，**不做平滑**；连续同色阶段合并为一条折线（见 3.3） |
| Z 色标 | `z=0…1` | `#4f7cff`→`#ff9f68` | 右上角标 `Z low` / `Z high` |
| 状态芯片 | 当前点的 XY、Z、`cursor_gain`、接合状态 | `#e9edf5` | 显示 `TRACK` 或 `LIFT / CLUTCH`，必要时显示 Lead 起笔状态 |
| 起点圆点 | 首点 | `#6ce5b1` | 半径 4 px |
| 终点圆点 | 末点 | `#ef7896` | 半径 4 px |
| 断线 | `cursor_engaged=false` 或无效帧 | 无 | 不连接前后点，避免把抬手画成假斜线 |
| 提示文字 | 无样本时 | `#536078` | 居中 "Record Lead or import a JSONL capture" |

### 3.3 采样与性能

- 采集帧率 200 Hz；重绘上限约 60 fps（轮询 16 ms）。
- 折线点数上限 2500，按整像素 XY 与 8-bit Z 去重、再超限抽稀；**只影响显示，编译仍用全量**。
- 坐标保留浮点，仅去重时取整（避免台阶状锯齿）。
- 抬手或无效帧增加 stroke 编号；不同 stroke 不连线。纯 Z 变化即使 XY 不动也保留为彩色点。
- 深度色分 10 阶，连续同阶段合并为一条 `create_line`；静止点圆点上限 200 个。逐段建图元时的实测为 **2039 图元 / 27 ms**，合并后为 **58–307 图元 / 4.7–5.7 ms**。

### 3.4 光标映射（数位板模型）

画布上的点不是原始计数，而是光标位置。映射是**绝对、边缘到边缘**的，与数位板一致：

```text
X: 0 … 65535                    → 0 … 1
Y: 32768 ± 65535·0.648/2        → 0 … 1      （Y 轴每物理距离只有 0.648 的计数）
cursor += alpha(z) · (target − cursor)
α: 1.00 @ z ≤ 4000  →  0.12 @ z ≥ 24000
```

- 手停在传感器边缘，光标就在画布边缘；画方形，屏幕上是方形。
- α 只影响**跟随速率**，不影响最终位置：静止时光标与手重合，抬高时快动作被阻尼。
- 抬起阈值 `z > 36000` 断开、`z < 30000` 重新接合；接合那一帧直接吸附并标记 `rebased`，编译器把它判为无效，避免追赶位移被读成转折。
- 画布显示、`compile_loop` 都通过 `make_cursor()` 取同一个模型，因此画面与音高不会各用一套。

### 3.5 与编译器的同源关系

画布画的是 `cursor_x / cursor_y`，编译器在 `pitch_source="cursor"` 下用同一个光标的 `y` 作为音高。唯一差异是显示层按 2500 点预算抽稀，编译使用全量。

## 4. 中栏：状态与事件表

| 元件 | 内容 | 说明 |
| --- | --- | --- |
| 状态行 | `READY` / `RECORDING` / `WAITING — Lead must start…` / `CAPTURED` / `COMPILED` / `RENDERED` / `EXPORTED` / `CLEARED` | 白色，随操作变化 |
| 诊断行 | `RRR.R Hz · queue N · draw X.XX ms · clip P% · N frames` | 灰色，每秒刷新；同时写入 `diagnostics/ui_<ts>.csv` |
| 进度条 | `maximum=128`，值为 `len(current_capture) % 128` | ⚠️ 既不是小节位置也不是 tick，只是帧数的循环，**会误导** |
| 事件表 | 9 列：`TRACK TICK NOTE DURATION VELOCITY SOURCE LANDMARKS DELTA COLOR` | 每行一个事件；`landmarks`/`delta` 列宽 118，其余 88；高度 6 行，为绘图区释放垂直空间 |

## 6. 状态机与元素表现

| 状态 | 画布 | 状态行 | 可点控件 |
| --- | --- | --- | --- |
| 空闲 | 显示上一段轨迹（若有） | `READY — selected <track>` | 全部 |

| 已编译 | 轨迹 + 事件表 | `COMPILED — <status> · N Lead events` | 全部 |
| 接收器缺失 | 不变 | `RECORDING — receiver executable not found; import JSONL instead` | 全部 |

## 8. 已知问题（按严重度）

| # | 问题 | 影响 |
| --- | --- | --- |
| 1 | **BPM / Swing 是死控件** | 用户调了没有任何效果，产生"改了没用"的不信任 |
| 2 | **PLAY 三个滑块是死控件** | 界面上承诺了一个尚未实现的表现层 |
| 3 | ~~没有接合（LIFT）指示~~ | 已在 XY 画布状态芯片显示 `TRACK` / `LIFT / CLUTCH` |
| 4 | ~~没有增益（GAIN）指示~~ | 已在 Lead cursor 预览中显示实时 `GAIN` |
| 5 | **进度条含义错误** | `frames % 128` 与音乐位置无关，会误读为小节进度 |
| 6 | 无小节/拍/tick 与小节内和弦高亮 | 产品规范要求录音时可见这些信息，缺失导致无法对齐乐句 |
| 7 | 无音域边界提示 | 光标撞到 0/1 时只是停住，没有"已在 G3/C5 边界"的提示 |
| 8 | ~~轴无刻度~~ | XY 俯视图已增加 0/0.25/0.5/0.75/1.0 刻度；Z 由色标表达 |
| 9 | 等待接合的状态文案过时 | 主状态行仍保留历史文案；画布芯片已显示实际起笔状态，后续可统一文案 |
| 10 | 事件表表头是缩写字段名 | `DELTA`/`LM`/`SRC` 对使用者不直观 |
| 11 | 日志宽度 30 字符 | 稍长的诊断会被折行，难以阅读 |
| 12 | 录制中其他按钮未禁用 | 录制时点 COMPILE 会隐式先停止，容易误操作 |
