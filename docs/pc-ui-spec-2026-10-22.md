## 2. 左栏（操作区）

自上而下，全部 `fill="x"`。

| 控件 | 类型 | 绑定 | 生效？ | 行为 |
| --- | --- | --- | --- | --- |
| TRACKS 六项 | 单选按钮组 | `selected_track` | ✅ | 切换录音目标轨；切换时状态行显示 `READY — selected <track>` |
| TAKE LABEL | 文本输入 | `take_label` | ✅ | 录音时作为原始文件名前缀：`<label>_<时间戳>.jsonl` |
| ● RECORD | 按钮 | — | ✅ | 清空当前缓存、重置滤波与光标、启动接收器子进程 |
| ■ STOP | 按钮 | — | ✅ | 终止接收器，把缓存并入该轨样本，状态显示 `CAPTURED — <track>: N reports` |
| COMPILE LOOP | 按钮 | — | ✅ | 先停止（若在录制），再编译六轨；状态显示 `COMPILED — <status> · N Lead events` |
| ▶ PLAY PREVIEW | 按钮 | — | ✅ | 未编译则先编译；渲染 `pc_receiver/synthwave_preview.wav`，用系统默认播放器打开 |
| CLEAR TRACK | 按钮 | — | ✅ | 清空当前轨的样本 |
| CLEAR ALL | 按钮 | — | ✅ | 清空全部六轨与事件表 |
| Import JSONL… | 按钮 | — | ✅ | 读入 capture；Lead 会重跑滤波与光标，非 Lead 轨直接追加 |
| Export Event JSON… | 按钮 | — | ✅ | 把事件表写成 JSON |
| Render WAV… | 按钮 | — | ✅ | 选择路径渲染 WAV |
| LEAD SPACE 两项 | 单选按钮组 | `mapping_mode` | ⚠️ 仅透传 | 传给 `compile_loop(mode=...)`；`gesture_aligned` 分支目前没有界面反馈 |

## 3. 中栏：画布

绘图区是**正方形**，居中，边长 `min(宽-56, 高-56)`；两侧留白属于正常现象，不是丢失的量程。

### 3.1 投影

等距投影，三个轴使用同一个像素尺度，因此单位步长在 X/Y/Z 上等长（实测 143.33 px）。

```text
输入：x, y = 光标位置（0–1）；z = 工作高度（0–1）
各减 0.5 后：
  screen_x = cx + (x - y) · 0.8660 · s
  screen_y = cy + ((x + y)/2 - z) · s
  s = 边长 / 2.4
```

### 3.2 图元清单

| 图元 | 数据来源 | 颜色 | 样式 |
| --- | --- | --- | --- |
| 背景网格 | 无（装饰） | `#182235` | 竖线每 80 px、横线每 60 px，铺满整幅画布 |
| 绘图区边框 | 正方形绘图区 | `#1d2740` | 1 px 矩形 |
| X 轴 | (0,0,0)→(1,0,0) | `#c96a6a` | 1 px，端点标 `X` |
| Y 轴 | (0,0,0)→(0,1,0) | `#6ac97a` | 1 px，端点标 `Y` |
| Z 轴 | (0,0,0)→(0,0,1) | `#6a9ac9` | 1 px，端点标 `Z` |
| 音级导线 | `DEFAULT_PITCH_SPACE.scale_pitches` 共 8 条 | `#27344d` | 沿 Y 轴方向横跨 X，左端标 MIDI 号（`Segoe UI 8`，`#536078`） |
| 轨迹折线 | `cursor_x` / `cursor_y` / `z_norm` | `#f3c969` | 2 px，**不做平滑**（拐角即用户所画） |
| 起点圆点 | 首点 | `#6ce5b1` | 半径 4 px |
| 终点圆点 | 末点 | `#ef7896` | 半径 4 px |
| 提示文字 | 无样本时 | `#536078` | 居中 "Record Lead or import a JSONL capture" |

### 3.3 采样与性能

- 采集帧率 200 Hz；重绘上限约 60 fps（轮询 16 ms）。
- 折线点数上限 2500，先按整像素去重、再超限折半抽稀；**只影响显示，编译仍用全量**。
- 坐标保留浮点，仅去重时取整（避免台阶状锯齿）。

## 4. 中栏：状态与事件表

| 元件 | 内容 | 说明 |
| --- | --- | --- |
| 状态行 | `READY` / `RECORDING` / `WAITING — Lead must start…` / `CAPTURED` / `COMPILED` / `RENDERED` / `EXPORTED` / `CLEARED` | 白色，随操作变化 |
| 诊断行 | `RRR.R Hz · queue N · draw X.XX ms · clip P% · N frames` | 灰色，每秒刷新；同时写入 `diagnostics/ui_<ts>.csv` |
| 进度条 | `maximum=128`，值为 `len(current_capture) % 128` | ⚠️ 既不是小节位置也不是 tick，只是帧数的循环，**会误导** |
| 事件表 | 9 列：`TRACK TICK NOTE DURATION VELOCITY SOURCE LANDMARKS DELTA COLOR` | 每行一个事件；`landmarks`/`delta` 列宽 118，其余 88；高度 8 行 |

## 6. 状态机与元素表现

| 状态 | 画布 | 状态行 | 可点控件 |
| --- | --- | --- | --- |
| 空闲 | 显示上一段轨迹（若有） | `READY — selected <track>` | 全部 |
| 录制中 | 每 16 ms 追加光标轨迹 | `RECORDING — <track>; <prompt>` | 仅 STOP；RECORD 无效 |
| 等待接合 | 轨迹为空时提示 | `WAITING — Lead must start at the left edge…`（文案已过时） | 仅 STOP |
| 已捕获 | 保留轨迹 | `CAPTURED — <track>: N reports` | 全部 |
| 已编译 | 轨迹 + 事件表 | `COMPILED — <status> · N Lead events` | 全部 |
| 接收器缺失 | 不变 | `RECORDING — receiver executable not found; import JSONL instead` | 全部 |

## 8. 已知问题（按严重度）

| # | 问题 | 影响 |
| --- | --- | --- |
| 1 | **BPM / Swing 是死控件** | 用户调了没有任何效果，产生"改了没用"的不信任 |
| 2 | **PLAY 三个滑块是死控件** | 界面上承诺了一个尚未实现的表现层 |
| 3 | **没有接合（LIFT）指示** | 抬高手后光标冻结，界面不说明原因，看起来像卡死 |
| 4 | **没有增益（GAIN）指示** | 用户无法知道当前是 1.0 还是 0.25 档，只能凭手感猜 |
| 5 | **进度条含义错误** | `frames % 128` 与音乐位置无关，会误读为小节进度 |
| 6 | 无小节/拍/tick 与小节内和弦高亮 | 产品规范要求录音时可见这些信息，缺失导致无法对齐乐句 |
| 7 | 无音域边界提示 | 光标撞到 0/1 时只是停住，没有"已在 G3/C5 边界"的提示 |
| 8 | 轴无刻度 | 只有 X/Y/Z 字母，没有数值或单位，难以判断幅度 |
| 9 | 等待接合的状态文案过时 | 仍写 "left edge"，与当前"首次接合"语义不符 |
| 10 | 事件表表头是缩写字段名 | `DELTA`/`LM`/`SRC` 对使用者不直观 |
| 11 | 日志宽度 30 字符 | 稍长的诊断会被折行，难以阅读 |
| 12 | 录制中其他按钮未禁用 | 录制时点 COMPILE 会隐式先停止，容易误操作 |

## 9. 如果重做一版，建议的信息层级

1. **顶部运输条**：小节/拍/tick、当前和弦（高亮）、BPM（真接线）、录音状态灯。
2. **画布左上角状态芯片**：`LIFT/HOLD`、`GAIN 0.25×`、`PITCH E4`、`Z 12.3k`，一眼看出为什么动得慢或不动。
3. **画布内加刻度**：三轴各画 5 个刻度点与数值（0/0.25/0.5/0.75/1）。
4. **去掉 PLAY 面板**，直到表现层真正实现；把 BPM/Swing 接上。
5. **进度条改成 8 小节划分**，随录制时间推进，而不是帧数循环。
6. **事件表表头改成中文/自然词**：轨道、tick、音高、时值、力度、来源、锚点、量化误差、色彩层。
